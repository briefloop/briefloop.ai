Think with your material.

BriefLoop is an Agent workbench that runs on your machine: it finds the sources around your question, drafts an editable report, scores it independently, and turns the feedback into experience the next run can use.

Why

Not another AI writing tool.

Material that stays on your machine, claims you can question, and a score kept separate from the draft — those three decide whether a report can be checked at all.

Material stays on your machine

The server listens on your machine only, so material, drafts and scores stay in your own directory. Closing the browser does not stop a running task.

Every claim can be questioned

Important claims are pinned to a line of source text, a PDF page, an Excel cell or an image — never a bare “as far as I know”.

Scoring is separate from drafting

The Evaluator scores independently and the Reviewer re-checks read-only. On a low score or a failed check, the draft and the issues are laid out for you to decide.

How it works

Four steps, from material to a traceable report.

Open each step to see what it does for you; the loop at the bottom makes every run easier than the last.

Traceable delivery

Every important claim can be questioned.

Delivery is not “the model says it is finished” — it means pinning each claim back to the line of source text, the PDF page or the cell it came from.

  • Claim binding Important claims are pinned to a line of source text, PDF page, Excel cell or image — never a bare “as far as I know”. Once the body text changes, the affected bindings are re-checked.
  • Read-only review The Reviewer checks the actual artifacts inside the audit bundle, read-only. Reads outside the bundle, shell access and writes are refused.
  • Audit bundle Export a zip that carries originals, excerpts or pointers only, chosen per source; it verifies offline against structure and consistency, and holds no credentials or hidden reasoning.
  • Version binding The final Word file is bound to its independent review and evidence version; earlier finals are kept, and a correction or update becomes a new version.

Export an audit bundle

python -m briefloop.audit_bundle /absolute/path/report-audit.zip
Four roles

One main Agent, three independent roles.

You only talk to BriefLoop; the agent that writes cannot declare its own draft acceptable — scoring, curation and proposals each stand apart.

Main Agent

BriefLoop

The one you talk to: it takes requirements and material, dispatches Scout to find sources and Analyst to write, then hands you an editable report.

Evaluator

Evaluator

Scores the artifacts and compares whether a candidate is a real improvement; each run uses a separate model session, so scoring never interferes with drafting.

Wiki Maintainer

Wiki maintainer

Turns feedback and execution observations into Wiki entries that the next research run benefits from directly.

Skill Proposer

Skill proposer

Proposes or improves Skills from the Wiki; a candidate is enabled only after it has been validated.

Capabilities

Enough, and transparent at every step.

From chat to final delivery inside one workbench; the activity of public tools and sub-agents stays visible throughout.

Chat workbench

Send messages, upload material, choose a model, add requirements; public tools and sub-agent activity are visible.

Workspace management

Open an existing directory or create one; each keeps its own conversations, sources, drafts, scores and Wiki.

Rich documents

Editable rich documents where format and content are versioned together; Markdown import and export included.

Recurring industry reports

Six section types trimmed to the industry and the task, exported to Word / WPS, with optional user templates and company background.

Charts and Excel

Reuse charts embedded in XLSX files or native charts; the Agent can build new ones from real data and register where they came from.

Images and PDF pages

Image originals are kept and previewed; individual PDF pages render on demand for vision models.

Conversation housekeeping

Archive, trash, restore, bulk archive; reports and the Wiki survive any conversation cleanup.

Learning loop

Feedback merges automatically after an edit; the Maintainer curates, the Proposer proposes, the Evaluator compares and decides.

Multiple runtimes, one bridge

Discovers the CLIs on your machine and bridges them uniformly: Codex, OpenCode, Claude Code, Kimi, Hermes, Reasonix and MiMo are connected; Kilo, Kiro and Vibe are wired and awaiting real-machine validation. One shared model catalogue, or type a model ID by hand.

Custom API protocols

Chat Completions, Responses and Anthropic Messages are explicitly supported; saving and testing stay separate.

Dedicated settings page

Models, API protocols and execution time limits configured in one place, serving both the browser window and a future shared Electron interface.

Synthetic weekly sample

examples/internal-weekly-report walks through generation, revision and Word export on synthetic material — no real data needed.

Get started

One repository, one command.

The first launch creates the .venv, installs the dependencies and the WikiSkill wheel shipped with the repository, then opens the local web app.

$ git clone https://github.com/Stahl-G/briefloop.git
$ cd briefloop
$ ./start.sh
  • Needs macOS and Python 3.11+, plus at least one supported CLI installed and authenticated (Codex, OpenCode, Claude Code, Kimi, Hermes, Reasonix and MiMo are connected; Kilo, Kiro and Vibe are wired and awaiting real-machine validation).
  • The first dependency install needs network access; the multi-runtime bridge needs Node.js 20+; using Tavily means configuring your own Tavily key.
  • The server listens on localhost only; closing the browser does not stop a running task.
  • Optional flags: ./start.sh --workspace ~/my-brief --port 8765 --no-open --backend opencode
