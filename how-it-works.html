工作原理

从问题到交付，四步闭环。

BriefLoop 把一个本地工作区变成可交付的报告流水线：你给目标和材料，它去研究、写作、独立评价，并把你的改稿沉淀成下一次的经验。

七个宿主 CLI 共享研究预算 独立评价会话 按需生成 Word
工作流

四步，把材料变成可交付的报告。

每一步都留下可查看的记录，任何一步都不会把"排队"说成"完成"。

01 · 需求与材料

说清读者、用途和篇幅

标题、目标、读者、时间范围、目标字数写在一个表单里；上传材料或直接开启联网让宿主去找公开来源。人工填写的小节只留"待填充"。

02 · 研究与写作

Scout 找来源，Analyst 写稿

研究预算由这次报告共享，Scout 决定查什么、留下哪些原件；Analyst 在来源范围内写作，引用回到具体的来源与定位。

03 · 独立评价

Evaluator 用独立会话评分

评价不读作者的自我评价，评分绑定它评的那一版稿件。需要时可以安排一次自动修订并复核，剩余问题留给用户。

04 · 交付与学习

Word 按需生成，改稿变成经验

Word 从固定版本生成并显示进度；正式交付绑定版本、模板、来源与核查记录。你的修改和反馈由 Wiki Maintainer 整理，验证后的技能才会启用。

可追溯交付

每条结论都能回到它的来源和版本。

追溯能力来自工作区保存的原件、定位和版本关系，不来自某一次模型回答。

版本绑定

评分、Word 导出和正式件都绑定具体稿件版本；继续编辑产生新版本，旧版本与已发布件保持可读。

来源即证据

原件、提取正文、定位与日期存在工作区里；模型摘要、搜索片段和评分都不是证据。

数据与缺口

"数据与缺口"按保存内容展示指标、计算和缺口，不调用模型；缺什么就列什么。

审计包

由用户选择导出范围，包内保留材料定位与核查处理记录，凭据和隐藏推理不进入导出。

角色

一个主 Agent，五个专职角色。

写稿的不给自己打分，评分的、整理经验的、提技能的各自独立。

BriefLoop

主 Agent

与你对话、规划研究、安排写稿与修订，使用主链模型。它是你在工作台里对话的那一方。

Scout

来源侦察

在共享预算内检索、抓取并保存公开来源。

Analyst

写稿

依据来源写作，引用回到具体定位。

Evaluator

评价

独立会话评分，并比较候选是否真的更好。

Wiki Maintainer

经验整理

把改稿与反馈整理成工作区 Wiki。

Skill Proposer

技能提议

从 Wiki 提出或改进技能，验证通过才启用。

预算与权限

花多少、能做多少，页面都写清楚。

预算属于一次报告，由这次报告里的所有侦察共享；权限属于宿主 CLI，BriefLoop 不会假装越权。

周报预设

12 次搜索尝试 · 60 个候选 URL · 18 个全文来源

三个数字都可以改，0 表示不提供这类新增额度。失败的搜索同样计次，达到上限后保留已有材料并列出缺口，不会自动加额。

月报预设

30 次搜索尝试 · 200 个候选 URL · 45 个全文来源

行业定期报告共用同一套预算；同一 URL 的直接获取、回退提取与重试只占一个全文来源。

Codex

可以强制只读或读写沙箱，并按轮控制联网搜索。

Opencode

用权限规则实现只读；模型写 provider/model。

桥接宿主

Claude Code、Kimi、Hermes、Reasonix、MiMo 按各自的权限模型运行；打开"联网"会放行它们自己的联网工具。

开发者

单仓库，接入新宿主只做三件事。

Python 负责存储、工具和确定计算；宿主 CLI 负责模型执行，两者通过已有的 jobs/events/Store 衔接。

一条命令起步

git clone 之后 ./start.sh 创建虚拟环境、安装依赖并打开网页；没有第二个仓库要 clone。

接入新宿主

实现 bridge 协议、加一条 catalog 条目、声明能力（permission_modes、steer、images），输入区会自动跟随这些能力。

测试与构建

npm ci && npm run build 打包前端与 bridge，pytest 跑行为测试；测试不调用真实模型或付费搜索。
