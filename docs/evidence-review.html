BRIEFLOOP / 使用指南

看依据与处理问题

区分已保存、已关联、已评分与已核查。

当前安装包：Mac 0.25.0、Windows 0.23.1。按钮与能力因渠道不同，以所装版本为准；不代表开发中功能已经随安装包发布。

前置条件

准备可备份的工作区；需要模型的操作须先完成宿主认证，并确认材料允许交给所选服务处理。

操作步骤

  1. 点击正文引用，查看来源标题、日期和摘录，并在必要时打开原件核对。
  2. 对重要数字核对主体、期间、单位、分母和计算。来源有冲突时保留差异，不把二手摘要当作解决依据。
  3. 读取当前版本的评分及具体问题；旧稿评分不能自动用于改写后的稿件。
  4. 0.25.0 可在设置中选择普通或严格审阅。普通模式在独立只读会话中核对稿件、来源与任务历史，支持 Codex、OpenCode 和 BriefLoop Agent；严格模式目前使用 BriefLoop Agent 强制限定核查材料包及可用工具。选择严格模式时，不支持的后端不会自动降级。查看本次实际模式与未核验项目；历史未记录模式的审阅不标为严格。
  5. 两种模式使用相同的事实与证据标准。把问题交回 BriefLoop 修订或人工修正并保存，再对新版本核查。普通工作稿下载与正式交付资格分开。

成功后应该看到什么

每个已处理问题应能在新版本中定位到修改，核查范围与未决问题仍清楚可见。来源链接或关联记录本身不是事实证明。

失败与边界

扫描 PDF、图片和缺少缓存的 Excel 公式可能需要额外核对。存在确定重大错误、核心证据缺口或未决重要冲突时，不应把稿件称为正式可交付。
