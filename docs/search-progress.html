BRIEFLOOP / 使用指南

搜索与任务进度

0.22.2：选择搜索渠道，明确报告期间，跟踪实际进展。

当前安装包：Mac 0.24.0、Windows 0.23.1。按钮与能力因渠道不同，以所装版本为准；不代表开发中功能已经随安装包发布。

前置条件

准备可备份的工作区；需要模型的操作须先完成宿主认证，并确认材料允许交给所选服务处理。

操作步骤

  1. 在“设置 → 运行与搜索”选择首选和允许的补充渠道。新工作区默认 Tavily 优先，并允许宿主自带搜索补充；博查和智谱需主动启用并配置 Key。
  2. 选择“检查跨市场覆盖并补缺”“仅在发现缺口时补查”或“只用首选”。Tavily、博查和智谱使用各自账户；没有搜索 Key 时，可选 DuckDuckGo 或宿主已有能力。
  3. 新建报告时检查截至日期、时间范围和时区。开始后保留本轮搜索策略与时间窗口；改设置影响新任务。定时报告每期重新计算相对时间。
  4. 在“我的报告”查看当前阶段、实际耗时、成功与失败搜索、已保存材料、研究轮次及审阅和修订进展。已有稿件可先打开；需要停止或恢复时沿用原任务。
  5. 在“研究预算 → 查看搜索记录”查看渠道、用途、耗时和错误；在“数据源”按发现渠道筛选材料。
  6. 0.22.2 在首页和新建报告中提供紧凑的研究深度、事实核查与 WikiSkill 选项。默认执行上限为 60 分钟；深度研究默认目标 10,000 字、上限 12,000 字，明确填写的篇幅优先。
  7. 在设置中调整“同时生成报告数”：默认 4，可选 1–16。Scout 并发单独设置。生成中可查看独立等待页，也可通过版本选择器切换已保存稿件；排队等待与执行时间分别显示。

成功后应该看到什么

阶段和数量来自已记录的执行与产物，不显示估算完成百分比。搜索失败会保留记录，并且消耗搜索尝试额度。

失败与边界

宿主原生搜索无法精确计量时显示未知，不混入受控 API 次数。搜索摘要、已保存材料和成功查询都不代表事实核实；公众号、小红书没有专门接入。
